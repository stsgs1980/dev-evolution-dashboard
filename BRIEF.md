# Бриф проекта: dev-evolution-dashboard

> **Статус**: DRAFT (обсуждается до создания репозитория)
> **Владелец**: stsgs1980
> **Дата**: 2026-10-22
> **Шаблон**: fork от `stsgs1980/webstorm-config`

## 1. Идея

Персональный аналитический дашборд, который по истории GitHub-аккаунта восстанавливает
траекторию профессионального развития разработчика: от первых коммитов до текущего
состояния. Не "витрина статистики", а инструмент рефлексии: где был рост, где плато,
какие навыки закрепились, какие инструменты появились и когда.

Ключевой принцип: дашборд оценивает **артефакты** (код, коммиты, конфиги, тесты),
а не человека. Любая интерпретация подписана как эвристика и имеет раскрываемую формулу
(см. экран `/methodology`).

## 2. Для кого

| Роль                     | Что получает                                                         |
| ------------------------ | -------------------------------------------------------------------- |
| Владелец аккаунта        | Ретроспектива: эры, точки перелома, слепые зоны, следующий шаг роста |
| Потенциальный наниматель | Объективная картина эволюции вместо списка репозиториев              |
| Сам агент-разработчик    | Набор чистых функций метрик + снапшот данных как фикстуры для тестов |

## 3. Стек

Порядок в этой таблице отражает не важность, а порядок решений: сначала выбирается
**один primitive-слой**, и только потом всё остальное подстраивается под него.

| Слой               | Решение                                                          |
| ------------------ | ---------------------------------------------------------------- |
| Framework          | Next.js (App Router) + React 19 + TypeScript strict              |
| Styling            | Tailwind CSS v4, тема в CSS через `@theme`, без tailwind.config  |
| **Дизайн-система** | **Untitled UI React** (copy-paste через CLI, MIT)                |
| **Primitives**     | **React Aria Components** — единственный primitive-слой          |
| Tokens             | Семантические токены Untitled UI, светлая и тёмная пара на токен |
| Блоки и паттерны   | shadcnblocks / shadcnstudio / shadcndeck как референс композиции |
| Charts             | Tremor raw (Recharts), перетемлённый на токены Untitled UI       |
| Icons              | `@untitledui/icons` основной слой; lucide только на добор        |
| Motion             | CSS-состояния React Aria + `motion` точечно, `LazyMotion`        |
| Drag and drop      | dnd-kit для реордера виджетов; React Aria DnD не дублируем       |
| Reference          | design.dev, base-ui — референсы, не зависимости                  |
| Testing            | Vitest (из шаблона)                                              |
| Data               | Снапшот JSON в репозитории, без API-вызовов в рантайме           |

### Почему Untitled UI первый, а не shadcn

Untitled UI React — не ещё один набор компонентов рядом с shadcn, а полноценный
дизайн-слой поверх React Aria: компоненты приходят исходниками через CLI, тему
задаёт свой семантический слой токенов, а поведение и доступность обеспечивает
React Aria от Adobe. Это даёт три вещи, критичные именно для этого проекта:

1. **Таблицы, деревья и data-grid** есть в React Aria как primitive, у Radix их нет.
   Портфель репозиториев и экран `/repos` живут на таблицах.
2. **Date range picker и календарь** есть только у React Aria. Фильтр периода
   с пресетами и кастомным диапазоном — обязательная функция v1.
3. **34 locale bundle, включая `ru-RU`** — локализация чисел и дат приходит
   системно, а не сборкой вручную через `Intl`.

### Роли остальных библиотек из списка

Спайн:

- **Untitled UI React** - все компоненты и секции. Задан владельцем как точка
  отсчёта UI, поэтому это решение, а не вариант.
- **React Aria** - primitive-слой, приходит вместе с Untitled UI. Один provider,
  один набор `data-*` состояний.

Порт (переносим паттерн, не код):

- **shadcnblocks / shadcnstudio / shadcndeck** - референс композиции: shell,
  sidebar, KPI-секции, таблицы с фильтрами. Стоят на Base UI, поэтому копировать
  код нельзя, только структуру.
- **magicui** - идеи эффектов (NumberTicker, BorderBeam), переписанные на своих
  токенах. Построен на Radix, как зависимость не подключается.

Не подключается в v1:

- **shadcn/ui** - с июля 2026 по умолчанию ставит Base UI, то есть второй спайн.
- **Base UI** - нет таблиц, деревьев и календаря; конфликтует с React Aria.
- **Radix UI** - дублирует React Aria, развитие части компонентов замедлилось.

Со своей темой:

- **Tremor** - графики на Recharts; палитры переопределяются на токены темы.
- **lucide-react** - добор иконок; основной набор `@untitledui/icons`.
- **design.dev** - визуальные ориентиры, не зависимость.

**Лицензия: только free tier.** PRO не приобретается. Бесплатный набор покрывает
базу и весь application UI, которого требует спека: таблицы, метрики, фильтр-бары,
заголовки страниц, сайдбар, модалки, графики line/bar/pie/radar. Только в PRO
остаются готовые страницы-примеры (40 дашбордов, 250+ страниц) и advanced-компоненты.

Практическое следствие: **готового дашборда не существует**, шелл и 8 экранов
собираются из бесплатных блоков руками. CLI технически умеет скачивать PRO-ассеты,
поэтому действует правило: добавляем только компоненты, помеченные в документации
как free, и ведём `docs/ui-components.md` со списком добавленного и ссылкой на
страницу компонента. PRO-компонент в проекте - нарушение лицензии.

**Правило одного спайна.** В проекте ровно один primitive-слой — React Aria. Всё, что
приносит второй (shadcn с Base UI по умолчанию, Radix, magicui), используется как
референс и переносится на свои компоненты. У каждого добавленного пакета в PR есть
одна строка обоснования: какую задачу решает и почему не решается тем, что уже есть.

**Токены не смешиваются.** Темы Untitled UI и Tremor конфликтуют: Tremor приносит
свои палитры. Поэтому палитры Tremor переопределяются на `chart-1..chart-6` из темы
Untitled UI, а не используются как есть.

## 4. Обязательные возможности (v1)

1. **Сбор данных офлайн-скриптом**: репозитории, коммиты, языки, чанж, манифесты
   зависимостей -> детерминированный JSON-снапшот в `data/snapshot/`.
2. **Слой метрик**: чистые TypeScript-функции, покрытые тестами, без побочных эффектов.
3. **Детекция эр**: разбиение истории на 3-6 периодов с автоматическими названиями.
4. **Индекс зрелости (DMI)**: составная оценка 0-100 с полностью раскрытыми весами.
5. **Экраны**: Обзор, Таймлайн эр, Стек, Портфель репозиториев, Ремесло (дисциплина
   коммитов), Инсайты, Методология.
6. **Инсайты**: детерминированные правила -> текстовые выводы с числами-доказательствами.
7. **Интерактив**: фильтры по периоду/репозиторию/языку, drill-down в репозиторий,
   реордер виджетов через dnd-kit с сохранением в localStorage.
8. **A11y и reduced-motion** как гейт, а не как пожелание.

## 5. Anti-goals

- Не оценивать человека и не выдавать эвристику за факт. Все выводы -> `/methodology`.
- Никаких запросов к GitHub API из браузера. Токен живёт только в `.env.local` скрипта.
- Никаких заглушек и фейковых данных в production-сборке (demo-данные только в тестах).
- Ровно один primitive-слой, React Aria. shadcn, Base UI и Radix не подключаются
  даже как зависимости: они дублируют спайн.
- Не анимировать против `prefers-reduced-motion`.
- Не превращаться в клон github-profile-readme: фокус на **динамике**, не на витрине.
- Не тянуть тяжёлые UI-киты целиком ради двух компонентов.

Следствия, уже внесённые в спеку:

1. **Горизонт 6 месяцев.** Эры заменяются фазами с двухнедельными бинами, `k` 2-3.
2. **Гигиена насыщена.** `health` делится на базовую гигиену и `depthScore`;

3. **`pushedAt` непригоден.** Массовое обновление 40+ репозиториев в один день;
   активность считается по датам коммитов.
4. **OSS-сигнал около нуля.** Вес снижен до 0.05, компонент показывается как
   "не применимо".

Правила сбора:

- Источник: GitHub REST v3 плюс blobless clone для истории коммитов.
- Вход: `--user stsgs1980`, `GITHUB_TOKEN` **обязателен**: без него 60 запросов
  в час, а нужно около 200 на статистику плюс список. Форма токена (fine-grained,
  только чтение, 90 дней) и место (`.env.local`) - `specs/token-setup.md`.
- Выход: `data/snapshot/latest.json` плюс датированный файл.
- Снапшот коммитится: дашборд детерминирован и работает без сети.
- Приватные репозитории: только агрегаты без имён, флаг `--include-private`,
  по умолчанию выключен.
- Бюджет: снапшот до 2 MB, коммиты по 500 на репозиторий, для пяти крупнейших
  (Agent-Qube, HH-Copilot, Z.Code.Guide, UX-Analyzer, Inventory) - `--since`.

## 7. Ограничения

- Anti-monolith из шаблона: 250 строк на файл, 200 на компонент, 50 на функцию,
  3+ `useState` -> кастомный хук. Для дашборда это означает дробление по `features/`.
- Все гейты шаблона должны быть зелёными (см. `docs/superpowers/prompts/08-quality-gates.md`).
- Объём снапшота: целевой бюджет <= 2 MB, иначе разбить по годам и грузить лениво.

## 8. Definition of Done для v1

1. `npm run data:collect -- --user <u>` создаёт валидный снапшот с нуля.
2. Все 7 экранов наполнены реальными данными, ни одного `TODO` в UI.
3. `npm run lint && npm run typecheck && npm run lint:css && npm run lint:md &&
npm run format:check && npm test && npm run check:file-length && npm run check:docs` -> все зелёные.
4. Покрытие тестами слоя метрик >= 80% по функциям.
5. Lighthouse a11y >= 95, CLS < 0.05, ни одного layout-shift на графиках.
6. README по `README.template.md` заполнен, CHANGELOG сгенерирован.
