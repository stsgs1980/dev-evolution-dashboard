# Kickoff: стартовый промт для dev-evolution-dashboard

Расширение шаблонного `docs/kickoff.md` под конкретный проект. Бриф обсуждается
заранее (в любом чате), в чат AI Assistant вставляется руками.

## Как использовать

1. Согласуйте `BRIEF.md` и снимите открытые вопросы.
2. Создайте репозиторий из шаблона `stsgs1980/webstorm-config`.
3. Скопируйте в него `docs/superpowers/` (specs, plans, prompts).
4. Вставьте блок «Промт» целиком в чат AI Assistant.
5. Дальше работа идёт фазами: один промт из `prompts/` на одну фазу.

## Промт

```text
БРИФ ПРОЕКТА: см. BRIEF.md в корне репозитория (dev-evolution-dashboard).

ЦЕЛЬ: аналитический дашборд, который по истории GitHub-аккаунта показывает траекторию
развития разработчика: активность, эволюцию стека, усложнение задач, зрелость инженерных
практик и точки перелома.

Ты работаешь в репозитории, созданном из шаблона webstorm-config. Порядок работы:

1. Прочитай BRIEF.md, docs/superpowers/specs/ и docs/superpowers/plans/. Если данных
   не хватает для старта - задай уточняющие вопросы и дождись ответа. Не додумывай
   требования сам.
2. Изучи и соблюдай правила шаблона: `.aiassistant/rules/AI Rules.md`,
   `docs/getting-started.md`, `docs/testing.md`, `docs/markdown.md`.
3. Проведи меня по фазам из `docs/superpowers/plans/dev-evolution-dashboard.plan.md`
   строго диалогом: на каждой фазе предложи варианты и жди моего выбора. Имя проекта,
   описание, README, стек и дизайн-направление я выбираю сам; за меня не решай.
4. На каждой фазе сначала прочитай соответствующий промт из
   `docs/superpowers/prompts/` и следуй его разделу "Definition of Done".
5. После каждой фазы запусти гейты и не иди дальше, пока они не зелёные:
   npm run lint, npm run typecheck, npm run lint:css, npm run lint:md,
   npm run format:check, npm test, npm run check:file-length, npm run check:docs.
6. Каждая фаза заканчивается коммитом в формате Conventional Commits.

ЖЁСТКИЕ ОГРАНИЧЕНИЯ:
- Никаких запросов к GitHub API в рантайме. Данные - только из закоммиченного снапшота.
- Токен GitHub живёт только в .env.local. Никогда не попадает в код, снапшот или коммит.
- Спайн UI: Untitled UI на React Aria. shadcn, Base UI и Radix не добавляем.
  Компоненты берём из Untitled UI, поведение и доступность - из React Aria.
- Любая метрика, которая интерпретирует человека, обязана иметь раскрытую формулу
  и пометку "эвристика" на экране /methodology.
- Anti-monolith из AI Rules действует: 250 строк на файл, 200 на компонент,
  50 на функцию, 3+ useState -> кастомный хук.

Начни с фазы 0: подтверди, что прочитал документы, перечисли, что понял, и задай
все уточняющие вопросы одним блоком. Кода на этом шаге не пиши.
```
