# Промт 04: модели — эры, DMI, инсайты (фаза 4)

```text
ФАЗА 4: Производные модели.

ЦЕЛЬ. Три детерминированные модели поверх метрик: сегментация истории на эры,
индекс зрелости DMI и правила инсайтов.

СТРУКТУРА src/shared/models/.
  eras/
    features.ts   - месячная матрица признаков из спеки 4.8
    normalize.ts  - z-нормализация, заполнение пропусков
    segment.ts    - агломеративная кластеризация соседних месяцев
    silhouette.ts - оценка качества разбиения
    merge.ts      - слияние сегментов короче 3 месяцев
    naming.ts     - генерация названий эр по доминирующим признакам
    index.ts      - detectEras(snapshot): Era[]
  dmi/
    dmi-weights.ts - веса, экспортируются отдельно, сумма = 1
    components.ts  - consistency, craft, complexity, depth, breadth, ossSignal
    index.ts       - computeDmi(snapshot, period): DmiResult
  insights/
    insight-rules.ts - 10 правил из спеки 4.9
    context.ts       - InsightContext, готовится один раз
    index.ts         - buildInsights(ctx): Insight[]
  types.ts

ТРЕБОВАНИЯ.
1. Детерминизм. Ни Math.random, ни Date.now внутри моделей. Дата "сегодня" приходит
   параметром. Сид фиксирован константой. Два прогона на одном снапшоте дают
   идентичный JSON - это проверяется снапшот-тестом.
2. k для кластеризации выбирается по максимальному силуэту в диапазоне 3-6.
   Если силуэт < 0.15 на всём диапазоне - вернуть одну эру на весь период
   с confidence "low" и пояснением в notes.
3. Минимум данных для сегментации: 12 месяцев истории. Иначе одна эра, confidence low.
4. Название эры: шаблон "<YYYY>-<YYYY>: <акцент>". Акцент выбирается по наибольшему
   отклонению z-признаков от среднего по истории. Никаких случайных слов.
5. DMI: веса только из dmi-weights.ts, сумма проверяется тестом (=== 1 с точностью
   1e-9). Результат округляется до целого, но компоненты отдаются с двумя знаками.
   Также возвращай delta12m: DMI на дату минус 12 месяцев.
6. Инсайты: каждое правило возвращает evidence с числами, периодом и именами
   репозиториев. Если evidence пуст - правило не срабатывает. Максимум 8 карточек,
   сортировка: attention, positive, neutral; внутри - по величине эффекта.
7. Тексты инсайтов на русском, без эмодзи, без оценочных суждений о человеке.
   Формулировки про артефакты: "в коммитах появились тесты", не "ты вырос".
8. Ни один файл не длиннее 250 строк; правила инсайтов держи компактными
   (одно правило <= 25 строк).

ТЕСТЫ.
- eras: детерминизм (два прогона), монотонность по времени (нет пересечений),
  покрытие всего периода без дыр, стабильность k на реальном снапшоте.
- dmi: сумма весов = 1; результат в [0, 100]; все компоненты в [0, 1];
  рост данных не уменьшает complexity.
- insights: на каждое правило два кейса - срабатывает на подготовленной фикстуре,
  не срабатывает на пустой. Проверка, что evidence непустой.

DoD.
[ ] detectEras даёт 3-6 эр на реальном снапшоте, без дыр в таймлайне.
[ ] computeDmi в [0, 100] на всех фикстурах, веса суммируются в 1.
[ ] Все 10 правил покрыты тестами, инсайт без evidence невозможен по типам.
[ ] Снапшот-тесты моделей в репозитории (vitest toMatchSnapshot).
[ ] Все 8 гейтов зелёные; коммиты feat(models): era segmentation,
    feat(models): dmi scoring, feat(models): insight rules.
[ ] Отчёт: список эр с датами и названиями, значение DMI и его компонентов.
```
