# Промт 11: продолжение после потери контекста

Используется, когда сессия прервалась, контекст сбросился, задача вернулась через день
или агент другой. Главная опасность здесь - агент начнёт заново то, что уже сделано,
или, наоборот, поверит state.md без проверки.

```text
ПРОДОЛЖЕНИЕ РАБОТЫ. Контекст предыдущей сессии утерян. Не начинай с нуля и не верь
журналу на слово.

ШАГ 1. Восстанови факты из репозитория, а не из памяти.
1. Прочитай .superpowers/state.md и .superpowers/ledger.md.
2. Проверь журнал против реальности:
   git log --oneline -20
   git status --porcelain
   git diff --stat HEAD
3. Сверь: последний коммит из state.md существует? рабочее дерево чистое?
   Если state.md расходится с git - верь git, а расхождение запиши в ledger как
   [WARNING] state drift: <детали>.

ШАГ 2. Проверь, что "зелёное" действительно зелёное.
Прогони гейты, не полагаясь на записи:
   npm run lint && npm run typecheck && npm run lint:md && npm run format:check \
     && npm test && npm run check:file-length -- --all && npm run check:docs
Если что-то красное, а в state.md записано зелёным - значит предыдущая фаза закрыта
некорректно. Это регресс: чини до продолжения, добавь запись в ledger.

ШАГ 3. Определи точку продолжения.
- Текущая фаза и следующий шаг берутся из state.md, но только после шагов 1-2.
- Если фаза закрыта частично, продолжай с первого незакрытого пункта её DoD,
  а не с начала фазы.
- Незакоммиченные изменения из прошлой сессии: сначала оцени их, потом либо
  докоммить как отдельный атомарный коммит, либо откати. Молча не оставляй.

ШАГ 4. Продолжай по промту 10 с того же места.
Соблюдай тот же контракт: дефолты из раздела 12 брифа, триггеры эскалации из
раздела 4, бюджет из раздела 15.

ПРАВИЛА ВОССТАНОВЛЕНИЯ.
- Не переписывай уже принятые ADR. Если решение кажется неверным - новое ADR,
  которое его отменяет, с причиной.
- Не удаляй записи из ledger.md.
- Не переписывай state.md целиком "с чистого листа": правь поля, а не файл.
- Если git log показывает коммиты, которых нет в ledger, - запиши их как
  [WARNING] untracked commit: <sha> <subject>.

ПЕРВЫЙ ОТВЕТ.
Только отчёт восстановления: что подтвердилось, что разошлось, где точка продолжения,
какой следующий шаг. Кода не пиши, пока не подтвердишь точку продолжения.
```

## Зачем это отдельным промтом

Автономный прогон почти всегда занимает больше одной сессии. Без процедуры
восстановления агент либо дублирует работу, либо доверяет устаревшему журналу и
закрывает фазу, которая на самом деле красная. Проверка журнала против `git log`
и повторный прогон гейтов - два действия, которые убирают оба сценария.
