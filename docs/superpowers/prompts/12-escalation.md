# Промт 12: отчёт об остановке и возобновление

Единственный способ, которым автономный агент имеет право обратиться к владельцу.
Формат фиксирован: иначе владелец получает поток сознания вместо решения.

## Шаблон отчёта об остановке

```text
[ESCALATE] Триггер <номер>: <название>

ЧТО ПРОИСХОДИТ
<2-3 предложения фактов. Без гипотез и оценок.>

ГДЕ
- фаза: <N>/11, <название>
- последний зелёный коммит: <sha> <subject>
- файлы: <список>
- состояние: <что закоммичено, что в рабочем дереве>

ПОЧЕМУ ОСТАНОВИЛСЯ
<расшифровка триггера: какое решение нельзя принять без владельца>

ЧТО УЖЕ ПРОБОВАЛ (для триггера 7 - обязательно)
| # | гипотеза | что сделал | результат |
| - | -------- | ---------- | --------- |
| 1 |          |            |           |
| 2 |          |            |           |
| 3 |          |            |           |

ВАРИАНТЫ РЕШЕНИЯ
A. <вариант> - плюсы / минусы / цена в правках / цена в откате
B. <вариант> - ...
C. <вариант> - ...

МОЯ РЕКОМЕНДАЦИЯ
<один вариант и одна строка почему. Рекомендация обязательна: владелец должен
иметь дефолт, если не хочет вникать.>

ЕСЛИ ВЛАДЕЛЕЦ МОЛЧИТ
<что произойдёт: прогон стоит на этом месте, ничего не удаляется, состояние
зафиксировано в state.md, рабочее дерево чистое.>

ЧТО НУЖНО ОТ ВЛАДЕЛЬЦА
<один вопрос, на который можно ответить одним словом или буквой варианта>
```

## Правила эскалации

1. Один отчёт - один вопрос. Два вопроса в одном отчёте дают два неполных ответа.
2. Рекомендация обязательна. Отчёт без варианта по умолчанию - недоработка.
3. Факты отделены от мнений. В разделе "ЧТО ПРОИСХОДИТ" нет слов "кажется" и "вероятно".
4. Перед остановкой рабочее дерево приводится в порядок: либо коммит, либо откат.
   Незакоммиченный мусор не оставляется.
5. `state.md` обновляется до отправки отчёта, а не после.
6. Триггер 6 (деструктив) - единственный, где вопрос задаётся до любого действия,
   а не после подготовки.

## Продолжение после ответа владельца

```text
ПОЛУЧЕН ОТВЕТ: <вариант A / текст>.

1. Запиши решение в ledger.md строкой: [DECISION] <что решили> | <почему> | <дата>.
2. Если решение архитектурное - оформи ADR в .superpowers/decisions/.
3. Обнови state.md: сними блокировку, поставь следующий шаг.
4. Продолжай по промту 10 с того же места.

Не пересказывай владельцу весь проект заново. Короткое подтверждение принятого
решения и первый шаг - достаточно.
```

## Что не является поводом для остановки

| Соблазн остановиться                     | Правильное действие                                 |
| ---------------------------------------- | --------------------------------------------------- |
| Неясно, как назвать компонент            | A1: назвать и идти дальше                           |
| Две библиотеки подходят одинаково        | A2: выбрать по разделу 11, записать в ledger        |
| Гейт красный впервые                     | Чинить самому, у тебя есть 3 попытки                |
| Хочется добавить ещё один экран          | Не добавлять: это скоуп, но и не блокер - в backlog |
| Не нравится формула метрики              | Не менять: предложение в backlog + ADR-предложение  |
| Тест падает из-за устаревшей фикстуры    | A1: обновить фикстуру                               |
| Спека молчит про пустое состояние экрана | A2: EmptyState по разделу дефолтов                  |
