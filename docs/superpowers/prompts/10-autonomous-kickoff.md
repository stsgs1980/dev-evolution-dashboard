# Промт 10: автономный запуск (режим B)

Один промт, который запускает весь прогон. Вставляется один раз, после создания
репозитория из шаблона. В отличие от промта 01, здесь нет "жди моего выбора".

````text
АВТОНОМНЫЙ РЕЖИМ. Ты ведёшь проект dev-evolution-dashboard от шаблона до тэга v1.0.0
самостоятельно. Владелец не отвечает на вопросы, кроме триггеров эскалации.

ЧИТАЙ ПЕРВЫМ ДЕЛОМ (в этом порядке):
1. AUTONOMOUS-BRIEF.md - контракт автономности, особенно разделы 3, 4, 10, 11, 13.
2. BRIEF.md - что за продукт.
3. docs/superpowers/specs/dev-evolution-dashboard.spec.md - модель данных и формулы.
4. docs/superpowers/plans/dev-evolution-dashboard.plan.md - фазы 0-11.
5. `.aiassistant/rules/AI Rules.md` - правила шаблона.
6. `docs/getting-started.md`, `docs/testing.md`, `docs/markdown.md`.

ТВОИ ПРАВА.
Ты решаешь сам: структуру файлов, имена, композицию UI, тексты, тесты, рефакторинг,
выбор библиотек из разрешённого списка (раздел 9 брифа), алгоритмы в заданных рамках.
Ты не решаешь: скоуп продукта, формулы метрик, схему снапшота, включение приватных
репозиториев, деплой.

ПОДГОТОВКА (сделай до первой строки кода).

1. Создай воркспейс:
   .superpowers/state.md
   .superpowers/ledger.md
   .superpowers/decisions/001-template.md
   .superpowers/reports/
   Скопируй шаблоны из docs/superpowers/templates/.
2. Добавь `.superpowers/` в .prettierignore одной строкой. Обоснование: format:check
   иначе проверяет журнал и падает на его разметке. Это единственная правка конфига,
   которую ты делаешь без ADR.
3. Заполни state.md: текущая фаза 0, последний зелёный коммит "нет", открытые
   допущения - из раздела 12 брифа, следующий шаг - фаза 1.
4. Проверь, что репозиторий не shallow clone (git rev-parse --is-shallow-repository).
   Если shallow - выполни git fetch --unshallow, иначе npm run changelog упадёт
   на фазе 11.

ЕСЛИ НЕ ХВАТАЕТ ВХОДНЫХ ДАННЫХ.
Единственный блокер на старте - отсутствие GitHub username. Если он не задан в брифе
и не передан владельцем, это триггер эскалации 1: остановись, напиши отчёт по формату
промта 12, дальше не иди. Не выдумывай аккаунт и не подставляй демо-данные.
Все остальные неясности решай дефолтами из раздела 12 брифа как [ASSUMPTION].

ПОРЯДОК РАБОТЫ.

Фаза 0. Напиши спеку и план сам, на основе брифа: уточни схему снапшота, список
метрик, набор экранов. Положи в docs/superpowers/specs/ и plans/. Если готовая спека
из пакета полная - используй её как есть, правки только через ADR.

Фазы 1-11. Проходи по плану. На каждой фазе:
  a. Прочитай state.md и соответствующий промт из docs/superpowers/prompts/.
  b. Составь план фазы на 5-9 шагов в state.md.
  c. Выполняй шаги, коммить атомарно.
  d. Прогони 8 гейтов:
     npm run lint && npm run typecheck && npm run lint:css && npm run lint:md \
       && npm run format:check && npm test && npm run check:file-length -- --all \
       && npm run check:docs
  e. Прогони саморевью по промту 99 на собственную работу. Blocker - чинить сразу.
  f. Обнови ledger.md, state.md, напиши .superpowers/reports/phase-NN.md.
  g. Переходи к следующей фазе, если DoD закрыт.

ПРАВИЛА, КОТОРЫЕ НЕ ОБСУЖДАЮТСЯ.

- console.log запрещён (ESLint allow только warn/error). В скриптах process.stdout.write.
- У каждой функции явный тип возврата, у экспортируемых - JSDoc.
- Тесты для scripts/ лежат в tests/, потому что vitest include покрывает только
  src/** и tests/**.
- Анти-монолит: 250 строк файл, 200 компонент, 50 функция, 3+ useState -> хук.
  При превышении выводи [ANTI-MONOLITH] Threshold exceeded: <reason> и дроби.
- Спайн UI: Untitled UI на React Aria. shadcn, Base UI и Radix не подключать.
- Маркдаун: 120 символов, aligned tables, язык у каждого fence, JSX в ```tsx,
  ASCII вместо стрелок и типографских символов, без эмодзи.
- Коммиты строго Conventional Commits, иначе CHANGELOG будет пустым.
- Обходы запрещены: --no-verify, HUSKY=0, правки хуков и линт-конфигов ради зелёного.

ФОРМАТ ОТВЕТА В ЧАТЕ.

Каждый ответ начинается строкой:
[INFO] Фаза <N>/11 - <название> - шаг <k> - гейты: <OK|FAIL>
Далее: что сделано, какие файлы, какие гейты, какой коммит, что дальше.
Раз в фазу - блок "Состояние" из state.md в сжатом виде.
Не пересказывай код целиком.

СТОП.
Останавливайся только по триггерам 1-8 из раздела 4 брифа. При остановке: не начинай
новых правок, зафиксируй state.md, выдай отчёт по промту 12 и жди.

ФИНАЛ.
После фазы 11 выдай финальный отчёт:
- таблица "фаза - коммиты - DoD - находки саморевью";
- список всех [ASSUMPTION] с причиной и способом отката;
- список ADR с однострочным решением;
- фактический вывод всех гейтов;
- backlog того, что не сделано, с причиной;
- вердикт: готово к v1.0.0 или нет, и почему.

Начинай с подготовки воркспейса и чтения документов. Первый ответ - только чтение,
state.md и план фазы 1. Кода в первом ответе не пиши.
````

## Чем этот промт отличается от промта 01

| Промт 01 (режим A)              | Промт 10 (режим B)                        |
| ------------------------------- | ----------------------------------------- |
| Спрашивает на каждом шаге       | Спрашивает только по 8 триггерам          |
| Владелец выбирает стек и README | Агент выбирает по разделу 9 брифа         |
| Спека приходит готовая          | Агент валидирует спеку и правит через ADR |
| Состояние в чате                | Состояние в `.superpowers/state.md`       |
| Просьба "проведи меня диалогом" | Требование "веди сам, отчитывайся блоком" |
