# Токен GitHub: форма, место, порядок подхвата

> **Дата**: 2026-10-22
> **Для чего**: сбор снапшота в `scripts/collect-github.ts` (фаза 2)
> **Главное**: токен не передаётся в чат и не попадает в репозиторий. Он живёт
> только в `.env.local` на машине, где запускается сбор.

## 1. Короткий ответ

| Вопрос       | Ответ                                                     |
| ------------ | --------------------------------------------------------- |
| Какая форма  | Fine-grained personal access token, **только чтение**     |
| Куда         | `<repo>/.env.local`, строка `GITHUB_TOKEN=github_pat_...` |
| Срок жизни   | 90 дней, отдельный токен только под этот проект           |
| В чат агенту | Нет. Сбор запускается локально, коммитится снапшот        |
| Отзыв        | Сразу после первого полного сбора, при необходимости      |

## 2. Создание токена

Порядок на github.com:

1. Settings -> Developer settings -> Personal access tokens -> **Fine-grained tokens**.
2. Generate new token.
3. **Token name**: `dev-evolution-dashboard-readonly`.
4. **Expiration**: 90 days (не "No expiration").
5. **Resource owner**: свой аккаунт.
6. **Repository access**: `Public repositories (read-only)`. Этого достаточно:
   в профиле 50 публичных репозиториев, приватные не анализируются.
7. **Permissions**:
   - `Contents`: **Read-only** - коммиты, файлы, история манифестов.
   - `Metadata`: **Read-only** - обязательное, включается само.
   - Всё остальное: **No access**. Ни `Administration`, ни `Issues`, ни `Actions`.

Почему не classic token: scope `repo` даёт запись во все репозитории, `public_repo`
тоже включает запись. Для сбора статистики нужна только одна операция - чтение.

Проверка, что токен работает и лимит поднялся (ожидается 5000 в час вместо 60):

```bash
curl -s -H "Authorization: Bearer $GITHUB_TOKEN" https://api.github.com/rate_limit
```

Без токена лимиты такие: core 60 запросов в час, search 10 запросов в минуту.
Для профиля нужно около 200 запросов core, то есть анонимно сбор не пройдёт.

## 3. Куда положить

Файл `.env.local` в корне репозитория:

```bash
GITHUB_TOKEN=github_pat_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Правила формата:

- Без кавычек, без `export`, без пробелов вокруг `=`.
- Одна переменная на строку, в конце перевода строки.
- Файл не коммитится, не копируется в снапшот, не скриншотится.

Вместе с ним создаётся `.env.example` (этот файл **коммитится**):

```bash
# Скопируйте в .env.local и вставьте свой fine-grained token (только чтение).
# Нужен для scripts/collect-github.ts: без него лимит 60 запросов в час.
# .env.local в .gitignore, в репозиторий не попадает.
GITHUB_TOKEN=
```

## 4. Как скрипт подхватывает токен

Порядок разрешения, реализуется в `scripts/collect/cli.ts`:

1. Переменная окружения `GITHUB_TOKEN` (если задана в шелле - приоритет).
2. Файл `.env.local` в корне репозитория.
3. `gh auth token`, если установлен GitHub CLI и выполнен `gh auth login`.
   Удобно: токен вообще не лежит в файле.
4. Ничего не найдено -> запуск в анонимном режиме с явным предупреждением
   `[WARNING]` и отказом от статистических эндпоинтов, чтобы не сжечь 60 запросов.

Технически чтение `.env.local` делается без дополнительных зависимостей:

```bash
# Node 22 умеет сам, флаг передаётся в tsx
node --env-file=.env.local --import tsx scripts/collect-github.ts --user stsgs1980
```

или внутри скрипта:

```typescript
process.loadEnvFile?.(".env.local");
```

Флаг `--env-file` предпочтительнее: не нужно ничего импортировать, а поведение
совпадает с тем, как Next.js читает `.env.local` в рантайме.

## 5. Куда токен класть нельзя

- **В чат с агентом.** Даже если агент в изолированной среде: токен уходит в
  историю переписки, а оттуда в логи. Восстановить невозможно, отзыв - единственная защита.
- В `BRIEF.md`, `AUTONOMOUS-BRIEF.md`, README, любой `.md`.
- В `docs/`, `data/`, тесты, фикстуры.
- В секреты CI: проект собирает снапшот локально, CI он не нужен.
- В `.env` (шаблон его тоже игнорирует, но стандарт для Next.js - именно `.env.local`).

Что защищает автоматически:

- `.gitignore` шаблона уже содержит `.env`, `.env.local`, `.env.*.local`.
- В репозитории включены **secret scanning и push protection**: если токен всё же
  попадёт в коммит, GitHub заблокирует push и пришлёт уведомление.

Проверка перед первым коммитом фазы 2:

```bash
git check-ignore -v .env.local     # должен показать правило из .gitignore
git grep -n "github_pat_"          # ожидается пусто
git status --porcelain             # .env.local не должен фигурировать
```

## 6. Порядок для двух режимов работы

Режим «сбор локально» (рекомендуется, токен не покидает машину):

1. Владелец создаёт токен, кладёт в `.env.local`.
2. Владелец запускает `npm run data:collect -- --user stsgs1980`.
3. Снапшот коммитится и уходит в репозиторий.
4. Агент работает только со снапшотом, токен ему не нужен вообще.

Режим «агент собирает сам» (если сбор делает агент в изолированной среде):

1. Владелец кладёт токен в окружение этой среды, а не в чат.
2. Если среда не поддерживает секреты окружения - выбрать первый режим.
3. После сбора токен отзывается в Settings -> Developer settings.

В обоих режимах действует правило: **в репозитории токена нет ни в какой момент**.

## 7. Ротация и отзыв

- Отзыв: Settings -> Developer settings -> Fine-grained tokens -> Revoke.
- Токен одноразовый по смыслу: собрали снапшот - отозвали. Новый сбор - новый токен.
- Один токен = один проект. Не переиспользовать в других инструментах.
- При утечке: отозвать, затем проверить историю `git log -p` на предмет попадания.
  Переписать историю - только после отзыва, иначе токен уже бесполезен как защита.
