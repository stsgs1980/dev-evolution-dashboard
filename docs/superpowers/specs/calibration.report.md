## 2. Что из этих фактов ломает спеку

### 2.1 Горизонт 6 месяцев, а не годы

Спека 4.8 требует минимум 12 месяцев истории для сегментации на эры. Реально есть 6.
При старом правиле модель честно деградировала бы до одной эры с `confidence: low` -
то есть главный экран проекта (`/timeline`) был бы пустым.

**Правка**: горизонт делится на месячные бины (6 точек) или двухнедельные (13 точек).
k сужается до 2-3. Термин "эра" заменяется на "фаза" при горизонте < 12 месяцев.
Минимум данных для сегментации снижается до 4 месяцев, ниже - одна фаза и `low`.

### 2.2 Гигиена репозиториев насыщена с первого дня

`health` в спеке 4.6 строится на флагах: README, LICENSE, тесты, CI, линтер,
описание, топики. В профиле описание есть у 48 из 50, топики у 47, лицензия у 48.
Метрика выдаст 98 из 100 почти для всех репозиториев, то есть перестанет различать
и убивает компонент `craft` в DMI: он будет равен 1.0 с первого дня наблюдения,
и рост не будет виден.

**Правка**: флаги делятся на два уровня.

| Уровень            | Флаги                                                                    | Роль             |
| ------------------ | ------------------------------------------------------------------------ | ---------------- |
| Базовая гигиена    | README, LICENSE, описание, топики                                        | floor, не растёт |
| Инженерная глубина | тесты, CI, релизы, hooks, CHANGELOG, покрытие, зависимости зафиксированы | различает        |

`health` остаётся, но дополняется `depthScore` из второго уровня. В DMI компонент
`craft` считается только по второму уровню, иначе он константа.

### 2.3 `pushed_at` непригоден как признак активности

У 40+ репозиториев `pushed_at` совпадает: 2026-10-13. Это массовое обновление
(лицензии, форматирование, метаданные), а не работа над каждым проектом.

**Правка**: `status` (Active/Dormant/Abandoned) и `activeSpan` считаются по датам
коммитов из `CommitRecord`, а не по `pushed_at`. `pushed_at` остаётся справочным полем.
В инсайты добавляется правило `mass-push`: если больше 50% репозиториев имеют коммиты
в один день, это событие обслуживания, а не всплеск разработки, и оно не должно
попадать в график активности как рост.

### 2.4 OSS-сигнал около нуля

3 звезды, 3 подписчика, 0 форков, 0 внешних PR. Компонент `ossSignal` в DMI даёт
0 и не изменится в обозримом будущем.

**Правка**: вес `ossSignal` снижается с 0.10 до 0.05, освободившиеся 0.05 уходят
в `craft` (0.25 -> 0.30). На экране компонент показывается как "не применимо"
с пояснением, а не как провал. Веса по-прежнему в `dmi-weights.ts` и суммируются в 1.

### 2.5 Набор инсайтов не совпадает с реальностью

Проверка десяти правил спеки 4.9 на фактических данных:

| Правило                 | Сработает? | Почему                                     |
| ----------------------- | ---------- | ------------------------------------------ |
| `conventional-adopted`  | Да         | 42% -> 93%, подтверждается напрямую        |
| `ci-adopted`            | Возможно   | зависит от даты первого workflow           |
| `tests-adopted`         | Возможно   | нужно считать по истории файлов            |
| `ts-migration`          | Нет        | TypeScript с первого дня, миграции не было |
| `abandonment-wave`      | Нет        | 0 архивных, 0 брошенных                    |
| `scaffold-heavy`        | Нет        | 0% scaffold-коммитов в выборке             |
| `breadth-without-depth` | Возможно   | 5 языков при 1223 коммитах, надо мерить    |
| `plateau`               | Нет        | активность непрерывная                     |

**Правка**: правила делятся на универсальные и профильные. Добавляются четыре,
которые описывают именно этот профиль:

- `mass-push` - обслуживание более 50% репозиториев в один день.
- `intensity-sprint` - больше 80 коммитов за 7 дней в одном репозитории
  (webstorm-config: 100 коммитов за неделю).
- `hygiene-from-day-one` - больше 90% репозиториев имеют лицензию и описание
  с момента создания: это факт о стартовых условиях, не о росте.
- `cluster-focus` - доля репозиториев в доминирующем тематическом кластере
  больше 40% (UI и дизайн-системы).

Правило без доказательств по-прежнему не рендерится, поэтому мёртвые правила
не показываются, но и не выбрасываются из кода.

### 2.6 Технологический словарь не совпадает со стеком

Дефолтный словарь в спеке 4.5 (prisma, drizzle, trpc, zustand, nestjs, three, d3)
почти не пересекается с профилем.

**Правка**: словарь строится по факту: react, tailwindcss, radix, typescript, vite,
next, node, python, fastapi, shell-скрипты хуков, а также собственные повторяющиеся
темы - design tokens, ui kit, agent guard, audit. Словарь живёт в
`data/tech-dictionary.ts` и покрывается тестом "каждый пакет встречается хотя бы раз".

## 3. Что это даёт дашборду

Разведка превращает проект из учебного в осмысленный: есть настоящая динамика
(42% -> 93% conventional), настоящая интенсивность (100 коммитов за неделю),
настоящий тематический сдвиг (дизайн-системы -> AI-governance), и настоящие
ограничения (6 месяцев, ноль OSS-сигнала), которые надо показать честно.

Правило "эвристика" остаётся в силе: "conventional ratio 42% -> 93%" - это факт
о коммитах, а не оценка человека.

## 4. Бюджет сбора данных

- **Репозиториев 50** - влезает в 100 запросов списка, пагинация не нужна.
- **Коммитов автора 1223** - blobless clone по репозиториям с `--since 2026-04-01`.
- **Суммарный размер ~339 MB** - клонировать только blobless, не полные копии.
- **Пять крупнейших**: Agent-Qube 50 MB, HH-Copilot 50 MB, Z.Code.Guide 48 MB,
  UX-Analyzer 43 MB, Inventory 35 MB - для них обязателен `--since` и лимит коммитов.
- **Статистика**: 50 репозиториев x 3 эндпоинта = 150 запросов, нужен токен и пауза.
- **Снапшот до 2 MB** - агрегаты без диффов, коммиты с лимитом 500 на репозиторий.

Без токена 60 запросов в час: полный сбор не пройдёт. Токен обязателен, хотя бы
fine-grained с правом `public_repo` на чтение.
