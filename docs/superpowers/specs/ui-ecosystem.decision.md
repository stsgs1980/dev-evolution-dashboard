# Решение: UI-экосистема

> **Статус**: accepted
> **Дата**: 2026-10-22
> **Уровень**: A3 (влияет на всю кодовую базу UI)
> **Заменяет**: прежнюю формулировку "Radix UI через shadcn/ui — единственный
> primitive-слой" в `BRIEF.md` и `spec` раздел 6.

## Контекст

Владелец зафиксировал список UI-ресурсов и поставил **Untitled UI React первым**.
В первом варианте брифа это было проигнорировано: спайном стал shadcn/ui на Radix,
а Untitled UI не упоминался вообще. Две фактические ошибки, которые к этому привели:

1. Список из 15 ссылок был прочитан как меню, из которого можно выбрать удобное,
   вместо приоритетов, заданных автором. Первый пункт - это решение, а не вариант.
2. Стек был собран по инерции: shadcn/Radix - самый распространённый дефолт,
   и он был взят без проверки, что даёт остальной список.

Проверка фактов на октябрь 2026:

- Untitled UI React построен на **React Aria** и Tailwind CSS v4, поставляется
  исходниками через CLI, MIT для базовых компонентов. То есть `react-aria` из списка
  не опциональное дополнение, а фундамент первого пункта.
- shadcn/ui с июля 2026 по умолчанию ставит **Base UI**, а не Radix. Значит связка
  "shadcn + Radix" в брифе была устаревшей.
- Radix UI перешёл под WorkOS, развитие части компонентов замедлилось, но проект
  не объявлен deprecated.

## Решение

Спайн проекта: **Untitled UI React (styled) + React Aria Components (primitives)**.
Единственный primitive-слой - React Aria. shadcn-семейство, Base UI, Radix и magicui
используются как референс или как паттерн для порта, но не как зависимости.

## Почему это лучше для этого проекта, а не просто "как просили"

| Аргумент        | Что даёт React Aria                      | Чего нет у Base UI / Radix        |
| --------------- | ---------------------------------------- | --------------------------------- |
| Таблицы         | Table, Tree, GridList, NavigationTree    | Нет ни одного                     |
| Период и даты   | DateRangePicker, Calendar, 13 календарей | Нет                               |
| Локализация     | 34 bundle, в том числе `ru-RU`           | Только пропсы `Intl`              |
| Доступность DnD | Есть, с паритетом клавиатуры             | Нет                               |
| Токены          | Готовая пара "светлая / тёмная" на токен | Своя палитра, конфликтует с чужой |

Спека требует трех вещей, которые упираются именно в эти пункты: табличный портфель
репозиториев (`/repos`), фильтр периода с кастомным диапазоном, и форматирование
чисел и дат по `ru-RU`. На Radix каждую из них пришлось бы собирать руками.

## Рассмотренные альтернативы

Варианты, которые отвергнуты, и почему:

- **shadcn/ui на Base UI.** Плюс: самая большая экосистема готовых блоков.
  Минус: нет таблиц, календаря и date picker; приносит второй слой токенов.
- **shadcn/ui на Radix.** Плюс: максимум примеров в интернете. Минус: развитие
  замедлилось, таблиц и компонентов даты нет.
- **Чистая React Aria без дизайн-слоя.** Плюс: максимальный контроль.
  Минус: весь визуал писать с нуля, недели работы вместо дней.
- **Смешать Untitled UI и shadcn.** Отвергнут как запрещённый: два provider-а,
  два primitive-слоя, конфликт токенов и фокус-ловушек.

Принят: **Untitled UI React на React Aria**. Плюс: таблицы, даты, локализация
и токены из коробки. Минус: PRO-компоненты платные, блоки маркетплейсов
придётся портировать.

## Бесплатный набор: что доступно без PRO

Лицензии нет, работаем на free tier. Это не блокер: бесплатная часть покрывает
именно то, из чего строится дашборд.

Бесплатно (MIT), компоненты и категории:

- База: buttons, inputs, select, multi select, checkboxes, radios, toggles, badges,
  tooltips, dropdowns, context menus, sliders, tags, textareas, progress indicators,
  avatars, illustrations.
- Application UI: tables (12), metrics (16), tabs (10), pagination (14),
  filter bars (8), page headers (6), sidebar navigations (5), header navigations (2),
  date pickers (6), empty states (3), drawers (20), modals (46), notifications (9),
  progress steps (18), tree views (4), command menus (9), content dividers (18),
  loading indicators (3), messaging (4).
- Графики: line and bar (4), pie (4), radar (1).
- Маркетинговые секции: по одному бесплатному варианту в каждой категории.
- Иконки: `@untitledui/icons`, бесплатный набор line-иконок (1100+).

Только в PRO:

- 250+ готовых страниц-примеров: 40 дашбордов, 40 settings, 105 marketing.
- Дополнительные advanced-компоненты и расширенные варианты секций.
- Полный набор иконок (4600+ в 4 стилях) и приватный npm-пакет.

Что это меняет в плане:

1. **Готового дашборда нет.** Шелл и все 8 экранов собираются из бесплатных блоков:
   page header, metrics, filter bar, table, charts, sidebar navigation. Работа
   фазы 8 не растёт, потому что в плане и не было копирования готового дашборда.
2. **Tremor сужается.** Line, bar, pie и radar берём из бесплатных графиков
   Untitled UI. Tremor остаётся только для типов, которых там нет: area,
   stacked area, scatter, tracker-календарь, sparkline. Одной библиотекой меньше.
3. **Иконок меньше, чем в PRO.** 1100+ line-иконок хватает для дашборда, но
   для редких глифов остаётся lucide как добор с единым stroke.
4. **Лицензионная граница.** CLI технически умеет скачивать PRO-ассеты. Правило:
   добавлять только компоненты, помеченные в документации как free. PRO-компонент
   в проекте - это нарушение лицензии, а не "мелкая неаккуратность".

## Последствия

Проще:

- Доступность: фокус-кольца, контраст, клавиатура уже сделаны в компонентах.
- Локализация: `ru-RU` приходит из React Aria, а не собирается вручную.
- Таблицы и фильтр периода делаются штатными компонентами.

Сложнее:

- Блоки из shadcn-маркетплейсов придётся портировать, а не копировать. Это время.
- PRO не приобретается: работаем на бесплатном MIT-наборе. Готовые страницы
  не используются, экраны собираются из бесплатных блоков.
- Иконочная система своя (`@untitledui/icons`), lucide - только добор.

Затронуто:

- `BRIEF.md` раздел 3, `spec` раздел 6, промты 01, 05, 06, 07, план фазы 1 и 5,
  автономный бриф разделы 9 и 11.

## Проверка

1. `package.json` не содержит `@radix-ui/*`, `@base-ui-components/*`, `shadcn`.
2. `react-aria-components` и `@untitledui/icons` присутствуют.
3. `src/` не содержит hex-литералов в компонентах графиков.
4. Поиск по `from "lucide-react"` в одном файле с `@untitledui/icons` даёт пусто.
5. Все интерактивные элементы проходят клавиатурой без дополнительных обработчиков.
