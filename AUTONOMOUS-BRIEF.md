# Автономный бриф: dev-evolution-dashboard (режим B)

> **Статус**: DRAFT, на согласование
> **Дата**: 2026-10-22
> **Отличие от `BRIEF.md`**: тот бриф для режима A (диалог на каждом шаге). Этот - для
> режима B, где агент проходит все фазы сам, без вопросов, и останавливается только
> по триггерам эскалации из раздела 4.
> **Опора**: `stsgs1980/webstorm-config`, факты репозитория в разделе 11.

## 1. Назначение

Дать агенту такой контракт, при котором он принимает все рабочие решения сам, но при
этом не выходит за скоуп, не изобретает требования и не теряет состояние между сессиями.
Автономность обеспечивается не разрешением "делай что хочешь", а тремя вещами:
делегированными полномочиями (раздел 9), машинно-проверяемым DoD (раздел 13) и
журналом решений, который переживает потерю контекста (раздел 6).

## 2. Режим A против режима B

| Ось                   | Режим A (диалог)            | Режим B (автономный)                    |
| --------------------- | --------------------------- | --------------------------------------- |
| Кто выбирает стек     | владелец на каждом шаге     | агент, из списка разрешённого           |
| Кто пишет спеку       | заранее, до старта          | агент, на фазе 0, по этому брифу        |
| Вопросы               | на каждом шаге              | только по триггерам эскалации           |
| Неясность             | спросить                    | принять допущение, записать, продолжить |
| Коммиты               | после согласования шага     | по DoD фазы, без согласования           |
| Проверка качества     | владелец читает каждый шаг  | гейты + саморевью перед закрытием фазы  |
| Состояние             | в голове владельца и в чате | в `.superpowers/state.md`               |
| Кто отвечает за выбор | владелец                    | агент, с обоснованием в ledger          |

Общее у режимов: бриф, спека метрик, фазы, гейты, anti-goals. Меняется распределение
решений, не содержание проекта.

## 3. Уровни автономии

Каждое решение агент относит к одному из уровней до того, как его принять.

| Уровень | Что охватывает                                 | Действие агента         |
| ------- | ---------------------------------------------- | ----------------------- |
| A1      | Локальная техника: имена, файлы, тесты, тексты | Делает молча            |
| A2      | Выбор из разрешённого списка (раздел 9)        | Делает, строка в ledger |
| A3      | Скоуп, данные, формула метрики, схема снапшота | ADR, затем делает       |
| STOP    | Триггер эскалации из раздела 4                 | Останавливается, отчёт  |

Расшифровка уровней:

- **A1** - всё, что не видно снаружи: имена переменных и компонентов, разбиение файлов
  внутри `src/`, структура тестов, порядок функций, формулировки подписей в UI.
- **A2** - библиотека из списка раздела 9, вариант компонента из Untitled UI, параметр
  алгоритма (k для кластеризации в 3-6, окно сглаживания), порядок виджетов.
- **A3** - новая функциональность, смена схемы снапшота, изменение формулы метрики,
  включение приватных репозиториев, всё, что увидит владелец в отчёте как сюрприз.

Ключевое правило: **агент не переводит задачу в STOP из-за неудобства**. STOP - только
когда продолжение требует угадать волю владельца или нарушить границу из раздела 10.

## 4. Триггеры эскалации

Останавливаться и спрашивать разрешено ровно в этих восьми случаях.

| #   | Триггер                                       | Пример                                                     |
| --- | --------------------------------------------- | ---------------------------------------------------------- |
| 1   | Нет входных данных, без которых нельзя начать | не задан GitHub username, а снапшот обязателен             |
| 2   | Скоуп расширяется                             | по ходу выяснилось, что нужен новый экран                  |
| 3   | Нужна зависимость вне списка                  | хочется подключить второй primitive-слой                   |
| 4   | Меняется формула или схема                    | спека требует правки метрики или полей снапшота            |
| 5   | Секреты и доступы                             | требуется токен с правами, которых нет, или утечка в git   |
| 6   | Деструктивная операция                        | force push, перезапись истории, удаление ветки, rm -rf     |
| 7   | Три неудачные попытки на гейте                | один и тот же красный гейт после трёх осмысленных подходов |
| 8   | Конфликт документов                           | бриф, спека и правила шаблона противоречат друг другу      |

Триггер 7 - единственный, который зависит от усилий: две попытки "на удачу" не считаются,
каждая попытка обязана иметь записанную гипотезу и проверку.

## 5. Протокол допущений

Вместо вопроса агент может принять допущение, если оно:

1. не меняет скоуп и не трогает данные владельца;
2. обратимо одной правкой;
3. имеет дефолт в разделе 12 или очевидный технический выбор.

Формат записи: тег `[ASSUMPTION]` в ответе + строка в ledger в виде
`[ASSUMPTION] <что допущено> | причина | как откатить`.

Допущение живёт до конца прогона и попадает в финальный отчёт отдельным списком.
Молчаливых допущений не существует: если не записано, значит не допущено.

## 6. Воркспейс `.superpowers/`

Шаблон уже выделил это место: `eslint.config.js` содержит `ignores: [".superpowers/**"]`
с комментарием "Agent workspace (superpowers briefs/ledger; never present in CI)".
Спеки и планы живут в `docs/superpowers/` (их не сканирует `check-docs`), а рабочий
журнал - в `.superpowers/`.

```text
.superpowers/
  state.md          - единственный источник истины о прогрессе
  ledger.md         - журнал решений, допущений и отклонений
  decisions/
    001-<slug>.md   - ADR на решения уровня A3
  reports/
    phase-NN.md     - отчёт по фазе, дублирует ответ в чат
```

Правила ведения:

- `state.md` перезаписывается после каждого чекпоинта, а не дополняется.
- `ledger.md` только дописывается; старые строки не правятся.
- В `state.md` четыре обязательных поля: текущая фаза, последний зелёный коммит,
  список открытых допущений, следующий шаг.
- Файлы держать в markdown-дисциплине шаблона: 120 символов, aligned tables.
  `lint:md` покрывает `**/*.md`, поэтому ledger тоже линтится.
- `.superpowers/` добавить в `.prettierignore` одной строкой: `format:check` иначе
  проверяет журнал и падает на его свободной разметке.

## 7. Петля работы

Цикл из `AI Rules.md` (Read, Plan, Execute, Record, Commit) расширяется проверкой.

```text
[1] READ     state.md + ledger + спека фазы + AI Rules
[2] PLAN     план фазы на 5-9 шагов, каждый шаг = проверяемый результат
[3] EXECUTE  шаг -> правка -> локальная проверка затронутого
[4] VERIFY   8 гейтов шаблона + саморевью по промту 99
[5] RECORD   state.md, ledger.md, ADR при A3, отчёт фазы
[6] COMMIT   Conventional Commits, атомарно, без --no-verify
```

Правила петли:

- Один коммит - одна законченная мысль. Три фикса красного гейта - три коммита.
- Пока гейт красный, следующая фаза не начинается. Незаконченная фаза не пушится.
- Саморевью (промт 99) прогоняется агентом на себя перед закрытием каждой фазы,
  находки уровня blocker устраняются до коммита.
- Отклонение от спеки допустимо только с ADR и с обновлением спеки в том же коммите.

## 8. Стоп-условия прогона

Прогон останавливается целиком, а не только текущая фаза, если:

1. Сработал любой триггер эскалации из раздела 4.
2. Две фазы подряд закрыты с открытыми находками severity blocker.
3. `npm run check:docs` или `npm run check:file-length` красные по причине, которую
   агент не может устранить без изменения правил шаблона.
4. Обнаружена утечка секрета в рабочем дереве или в истории.
5. Израсходован бюджет из раздела 15.

При остановке агент не начинает новых правок, фиксирует состояние, пишет отчёт по
формату промта 12 и ждёт.

## 9. Делегированные полномочия

Агент решает сам, без согласования:

| Область          | Что разрешено                                                          |
| ---------------- | ---------------------------------------------------------------------- |
| Структура файлов | любое разбиение внутри `src/`, пока живут лимиты анти-монолита         |
| Имена            | файлы, компоненты, хуки, функции, тесты, ветки, scope коммитов         |
| UI               | композиция, порядок виджетов, тексты на русском, состояния             |
| Библиотеки       | untitled-ui, react-aria, tremor, dnd-kit, motion, nuqs, zod, octokit   |
| Алгоритмы A2     | перцентили, нормализация, k для кластеризации в 3-6, веса виджетов     |
| Тесты            | структура, фикстуры, порог покрытия не ниже 80% для метрик             |
| Рефакторинг      | дробление файлов, вынос хуков, переименования внутри проекта           |
| Документация     | README, docs, комментарии, JSDoc, тексты /methodology                  |
| Зависимости      | обновление в пределах semver-minor, кроме заблокированных в разделе 11 |

Не делегировано: скоуп продукта, формулы метрик из спеки, состав данных снапшота,
включение приватных репозиториев, деплой, публикация, доступы.

## 10. Жёсткие границы

Нарушение любого пункта = провал прогона, независимо от качества остального.

1. Ни одного сетевого вызова к GitHub вне `scripts/`.
2. Ни одного секрета в репозитории; `git grep` по `ghp_`, `github_pat_`, `.env` пуст.
3. Никакой фейковой даты в UI: только данные из снапшота.
4. Ни одного `TODO`, `mock`, `stub`, закомментированного кода в `src/` и `data/`.
5. Ни одного обхода хуков: `--no-verify`, `HUSKY=0` в коммитах запрещены.
6. Ровно один primitive-слой: React Aria. Второго (shadcn, Base UI, Radix) нет.
7. Ни одной эвристики без раскрытой формулы на `/methodology`.
8. Ни одного push в `main` при красных гейтах.
9. Никаких правок `.husky/`, `eslint.config.js`, `tsconfig*.json` для обхода проверок.
   Правка допустима, только если добавляет строгость, а не снимает.
10. Ни одного PRO-компонента Untitled UI. Лицензии PRO нет. CLI умеет скачивать
    PRO-ассеты, поэтому статус free проверяется по странице компонента перед каждым
    `untitledui add`, а факт добавления пишется в `docs/ui-components.md`.
    Нужного компонента нет в free - собираем сами на React Aria.

## 11. Факты репозитория, обязательные к учёту

Извлечено из конфигов шаблона. Каждый пункт уже ломал чей-то прогон, поэтому читать
до первой строки кода, а не по мере падения гейтов.

Линтинг и типы:

- `eslint.config.js` содержит `ignores: [".superpowers/**"]` -> журнал агента держать
  там, ESLint его не тронет; спеки и планы - в `docs/superpowers/`.
- `no-console: ["error", { allow: ["warn", "error"] }]` -> `console.log` запрещён,
  в скриптах `process.stdout.write`.
- `@typescript-eslint/explicit-function-return-type: error` -> у каждой функции явный
  тип возврата, включая стрелочные.
- `jsdoc/require-jsdoc` с `publicOnly` покрывает стрелочные функции -> JSDoc обязателен
  над экспортируемыми компонентами.
- `noUnusedLocals` и `noUnusedParameters` в strict tsconfig -> неиспользуемый параметр
  ломает `typecheck`.
- `.gitattributes`: LF для ts/js/md/json/yml, CRLF только для cmd/bat/ps1 ->
  переводы строк вручную не править.

Тесты:

- `vitest.include` покрывает только `src/**` и `tests/**` -> тесты для `scripts/`
  класть в `tests/`, иначе они молча не запустятся.
- `tests/**` в ESLint: unicode-policy выключен, globals включены -> фикстуры
  с эмодзи допустимы только там, в `src/` - никогда.
- `check-file-length` освобождает `*.test.*`, `*.spec.*`, `tests/` -> длинные тестовые
  файлы дробить не требуется.

Гейты и их поведение:

- `check-file-length` по умолчанию смотрит только staged файлы -> перед проверкой
  `git add`, для полного прогона `--all`.
- `check-docs` сканирует `README.md`, `README.template.md`, `docs/` и исключает
  `docs/superpowers/` -> планы и спеки жить там, не в `docs/prompts/`.
- `check-docs`: `KNOWN_FUTURE_SCRIPTS = ["dev"]` -> в доках ссылаться только
  на существующие npm-скрипты, кроме `dev`.
- `format:check` = `prettier --check .` -> форматируется всё, включая `.md` и JSON.
- `.prettierignore` не содержит `.superpowers/` -> добавить строкой, иначе гейт красный.
- `lint:md` = `markdownlint "**/*.md"` -> ledger и отчёты тоже под 120 символов
  и aligned tables.
- `prettier-plugin-organize-imports` и `prettier-plugin-tailwindcss` -> порядок
  импортов и классов перезаписывается `format`, спорить с ним бессмысленно.

UI-экосистема (см. `docs/superpowers/specs/ui-ecosystem.decision.md`):

- Спайн: Untitled UI React на React Aria. Один primitive-слой, один provider.
- shadcn/ui с июля 2026 по умолчанию ставит Base UI, а не Radix -> как зависимость
  не подключается, только как паттерн для порта.
- React Aria даёт Table, Tree, DateRangePicker, 34 locale bundle и доступный DnD ->
  таблицы, фильтр периода и `ru-RU` не собираем руками.
- Base UI и Radix не дают таблиц и календаря -> в v1 не подключаются.
- magicui построен на Radix -> только как идея эффекта, переписать на своих токенах.
- Tremor приносит свою палитру -> переопределить на `chart-1..chart-6` темы.
- Free-набор Untitled UI покрывает базу и application UI: tables, metrics, tabs,
  pagination, filter bars, page headers, sidebar navigation, date pickers, modals,
  drawers, empty states, charts (line, bar, pie, radar).
- В PRO остались только готовые страницы-примеры (40 дашбордов, 250+ страниц)
  и advanced-компоненты -> шелл и экраны компонуются из бесплатных блоков.
- Free-иконок 1100+ line -> для редких глифов lucide как добор, единый stroke.
- Иконки: `@untitledui/icons` основной, lucide только добор, не в одном файле.

Окружение и релиз:

- `engines.node >= 22.22.2`, `.nvmrc` 24.15.0, `.npmrc` с `engine-strict=true`,
  CI job `floor` на 22.22.2 -> не использовать API, которых нет в Node 22.22.2.
- Dependabot игнорирует мажоры `eslint`, `typescript`, `@types/node` -> эти мажоры
  не поднимать, они заблокированы плагинами.
- `generate-changelog` падает на shallow clone -> перед релизом `git fetch --unshallow`.
- `conventional-changelog -p angular` -> нестандартные коммиты в CHANGELOG не попадут.
- `.husky/pre-commit`: lint-staged + file-length, `pre-push`: typecheck + test ->
  локально те же гейты, что в CI, обойти нельзя.
- `tsconfig.include`: `src`, `**/*.ts`, `**/*.tsx` -> `typecheck` покрывает и `scripts/`.

## 13. DoD автономного прогона

Машинно-проверяемое. Агент обязан приложить фактический вывод, не пересказ.

```bash
npm ci
npm run data:validate
npm run lint
npm run typecheck
npm run lint:css
npm run lint:md
npm run format:check
npm test
npm run check:file-length -- --max-lines=250
npm run check:docs
git grep -n -E "ghp_|github_pat_" || true     # ожидается пусто
git status --porcelain                          # ожидается пусто
```

Дополнительно руками, но по чеклисту:

- [ ] Восемь маршрутов открываются на реальном снапшоте.
- [ ] `/methodology` содержит формулу DMI дословно как в спеке.
- [ ] Каждый инсайт имеет непустой evidence.
- [ ] При `prefers-reduced-motion: reduce` анимаций нет.
- [ ] Реордер виджетов работает с клавиатуры и переживает перезагрузку.
- [ ] Ни одного `TODO` и `mock` в `src/` и `data/`.
- [ ] Все файлы в лимитах анти-монолита.
- [ ] CHANGELOG сгенерирован, тэг `v1.0.0` создан.

## 14. Приёмка владельцем

Десять пунктов, по которым принимается результат. Всё остальное - на усмотрение агента.

1. Открыл репозиторий: `npm ci && npm run dev` работает с первого раза.
2. Снапшот воспроизводится командой `npm run data:collect -- --user <u>`.
3. Числа на экранах совпадают с выводом `npm run report`.
4. Формулы на `/methodology` совпадают со спекой.
5. Ни один инсайт не звучит как оценка человека.
6. Список `[ASSUMPTION]` в финальном отчёте не содержит решений, которые я бы отменил.
7. Ledger читается как история: видно, почему принято каждое решение A2 и A3.
8. Все 8 гейтов зелёные, CI зелёный на `main`.
9. Диффы коммитов атомарные, сообщения по Conventional Commits.
10. В backlog честно выписано то, что не сделано.

## 15. Бюджет прогона

| Параметр                         | Лимит                                             |
| -------------------------------- | ------------------------------------------------- |
| Фаз за один непрерывный прогон   | 3, далее чекпоинт и продолжение отдельной сессией |
| Коммитов на фазу                 | 6                                                 |
| Новых runtime-зависимостей всего | 10                                                |
| Попыток на один красный гейт     | 3                                                 |
| Открытых blocker-находок         | 0 перед закрытием фазы                            |
| Размер снапшота                  | 2 MB                                              |

Бюджет нужен, чтобы автономность не превращалась в бесконечный цикл правок. Достижение
лимита - не провал, а сигнал к чекпоинту и отчёту.
